# Интерактивная установка IGProxy

## Запуск

```bash
chmod +x IGProxy
sudo ./IGProxy
```

Установщик распакует проверенный встроенный релиз во временный каталог и
запустит русскоязычный мастер. До экрана подтверждения выполняются только
проверки: работающие службы и существующая конфигурация не изменяются.
При следующем обновлении замените на сервере этот же файл `IGProxy` и снова
запустите его: версионные имена установщику не нужны.

На коротких экранах выбора достаточно нажать цифру — Enter не требуется.
Пункт `0 · Назад` на экране режима возвращает к выбору роли сервера, а на
первом экране закрывает мастер без изменений.

## Экраны мастера

### 1. Роль сервера

- **Центр управления + прокси** — первый сервер сети. Здесь работают единый
  Telegram-бот, web-админка, реестр узлов и собственный MTProxy.
- **Дополнительный прокси-узел** — региональный или резервный сервер без
  отдельного бота. Он подключается к центру исходящим HTTPS-запросом и
  появляется отдельной клиентской кнопкой в общем боте.
- **Автономный сервер** — независимая установка без единого центра.

Если IGProxy уже установлен, мастер сохраняет его текущую роль. Для смены
архитектуры сначала следует создать бэкап и выполнить перенос отдельно.

### 2. Проверка сервера

Мастер показывает ОС, архитектуру, память, диск, публичный IPv4, занятые порты,
firewall и обнаруженную установку `telemt`. Если порт `443` занят чужим
сервисом, он не останавливается и вообще не предлагается. Нажмите Enter, чтобы
принять рекомендованный свободный порт, либо сразу введите собственный номер,
например `9443`.

### 3. Публикация

- **Свой домен и сайт** — локальная витрина, HTTPS и кнопка подключения.
  Проверяются DNS, сертификат, порт `80` и внутренний порт сайта.
- **Только прокси** — без публичной витрины. Подходит дополнительному узлу,
  которому достаточно клиентской кнопки в общем Telegram-боте.

Центру нужен домен с рабочим HTTPS: через него дополнительные узлы безопасно
регистрируются и отправляют heartbeat. Каждый сервер с включённым сайтом
показывает собственную локальную витрину; сайты между узлами не копируются.

Если для домена уже есть пригодный сертификат в `/etc/letsencrypt/live`,
мастер проверит имя и срок действия, покажет найденную линию и подключит её без
повторного выпуска. Порт `80` в этом случае не блокирует установку на этапе
firewall-проверки. Если сертификат отсутствует или истекает менее чем через
сутки, мастер запускает обычную проверку Let's Encrypt.

### 4. Витрина сайта

В новом мастере нет старого каталога сторонних тем. Он показывает только
встроенные страницы IGProxy: рандомную витрину из 10 разных композиций, каждую
из этих композиций отдельно и три дополнительные авторские страницы. Они уже
находятся внутри проверенного релиза и не скачиваются с GitHub.

### 5. Параметры

Мастер попросит только данные, которые нужны выбранной роли: домен, публичный
порт, подпись клиентской кнопки, токен бота или адрес центра. Секреты не
показываются в итоговом плане и не передаются в аргументах процессов.

Для нового узла в центре заранее создаётся одноразовый код:

```bash
sudo gotelegram
```

Далее: **Сеть серверов → Создать код подключения**. Код действует 30 минут и
после успешного подключения больше не принимается.

### 6. План и подтверждение

Перед записью файлов мастер показывает выбранную схему, публичные адреса,
порты, службы и предупреждения. Установка начинается только после явного
подтверждения.

### 7. Применение и проверка

Перед обновлением создаётся root-only транзакционный снимок. Сохраняются все
записи раздела `[access.users]`, включая `main`, `res` и дополнительные ключи,
а также расширенные настройки IGProxy. Затем мастер обновляет компоненты,
проверяет конфигурации, запускает службы и выполняет итоговый health-check.
При ошибке изменения откатываются к снимку.

## После установки

- Меню управления: `sudo gotelegram`
- Локальная админка: `http://127.0.0.1:1984`
- SSH-туннель:

```bash
ssh -N -L 127.0.0.1:1984:127.0.0.1:1984 root@IP_СЕРВЕРА
```

Для дополнительного узла не требуется открывать служебный входящий порт:
агент сам связывается с центром по HTTPS. В центре узел появится в разделе
сети, а его включённая клиентская кнопка — в общем Telegram-боте.
